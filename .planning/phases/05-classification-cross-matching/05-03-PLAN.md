Replace the stub with full implementation. Receives output dict from `classify_objects` (keys: `observation_uuid`, `objects_classified`, `model_version`, `status`).

**Main function: `detect_anomalies(self, classification_result: dict) -> dict`**

This is the **ninth and final task** in the pipeline chain. It MUST set `PipelineStatus.completed` on success (pipeline finalization ownership transferred from generate_cutouts in Plan 01).

1. Create `ProcessingStep(step_name="detect_anomalies", step_status=StepStatus.running)`
2. Query all `ObjectClassification` records for this observation's objects (most recent per object via `ORDER BY classified_at DESC`, grouped by object_uuid -- latest classification only)
3. Query all `AstronomicalObject` records for cross-match and catalog info

4. **IsolationForest scoring:**
   - Extract feature matrices from `ObjectClassification.feature_vector` JSONB for all objects
   - Use the same `FEATURE_COLUMNS` list from `pipeline/ml_models/classifier.py`
   - Impute NaN/-999 with column medians (same imputation as classifier)
   - If >= 10 objects (need minimum for meaningful anomaly detection):
     - Fit `IsolationForest(n_estimators=200, contamination=settings.classification_anomaly_contamination, random_state=42, n_jobs=-1)`
     - `anomaly_scores = iso_forest.score_samples(feature_matrix)` -- lower = more anomalous
     - `anomaly_predictions = iso_forest.predict(feature_matrix)` -- 1=normal, -1=anomaly
     - Save trained model to S3: `joblib.dump(iso_forest, temp_path)` -> upload to `settings.classification_anomaly_model_s3_key` in `settings.s3_bucket_models`
   - If < 10 objects: skip IsolationForest (not enough data), set all scores to 0.0, log warning

5. **Multi-signal anomaly flagging** (per user decision: ANY single signal triggers a flag):
   For each object, check ALL of:
   - **Signal 1 - Feature vector outlier:** `anomaly_prediction == -1` from IsolationForest
   - **Signal 2 - Catalog disagreement:** ML `predicted_object_type` disagrees with `classified_object_type` from catalog (and both are not "unknown")
   - **Signal 3 - No catalog match:** Object has zero `CatalogCrossMatch` records across all 4 catalogs
   - **Signal 4 - Unusual morphology:** statmorph `flag >= 2` (from feature_vector dict)
   - **Signal 5 - Low ML confidence:** `classification_confidence_score < 0.3`

   If ANY signal fires AND `predicted_object_type != "artifact"` (per user decision: artifacts NOT flagged as anomalies):
   - Set `is_anomaly_flagged = True`
   - Build human-readable `anomaly_explanation` string listing ALL triggered signals:
     - Example: "Feature vector outlier (IsolationForest score: -0.42); No catalog match within search radius; ML confidence below threshold (0.18)"
   - Set `anomaly_score` = IsolationForest score (or 0.0 if IF skipped)

6. **Update records:**
   - Update each `ObjectClassification` record: `is_anomaly_flagged`, `anomaly_score`, `anomaly_explanation`
   - Update each `AstronomicalObject`: `is_anomaly_flagged` (the indexed column for fast queries)
   - Batch DB flush every 50 objects

7. **Pipeline finalization** (this task owns PipelineStatus.completed):
   - Set `observation.pipeline_status = PipelineStatus.completed`
   - Create completed ProcessingStep with metadata: `{objects_scored, anomalies_flagged, isolation_forest_fit: true/false, signals_distribution: {feature_outlier: N, catalog_disagreement: N, no_catalog_match: N, unusual_morphology: N, low_confidence: N}}`

8. Return dict: `{observation_uuid, objects_scored, anomalies_flagged, status: "completed"}`

**Error handling:**
- On IsolationForest failure: log warning, continue with remaining 4 signals (feature outlier signal just doesn't fire)
- On task-level exception: mark ProcessingStep as failed, mark Observation as `PipelineStatus.failed`, re-raise

**api/routers/objects.py:**

Create new router with 3 endpoints (per user decision: basic API endpoints in this phase).

Follow existing patterns from `api/routers/ingest.py` for FastAPI router setup, DB session dependency injection, and response models.

**Endpoint 1: GET /api/objects/{object_uuid}/classifications**
- Returns all classification records for an object (append-only history, ordered by `classified_at DESC`)
- Query `ObjectClassification` filtered by `object_uuid`
- Response model: list of dicts with fields: `classification_uuid`, `predicted_object_type`, `classification_confidence_score`, `ml_model_version`, `feature_extractor_version`, `feature_vector`, `is_anomaly_flagged`, `anomaly_score`, `anomaly_explanation`, `classified_at`
- 404 if object_uuid not found in AstronomicalObject table

**Endpoint 2: GET /api/objects/{object_uuid}/cross-matches**
- Returns all catalog cross-match records for an object
- Query `CatalogCrossMatch` filtered by `object_uuid`, ordered by `angular_separation_arcseconds ASC`
- Response model: list of dicts with fields: `match_uuid`, `catalog_name`, `catalog_source_id`, `angular_separation_arcseconds`, `match_probability_score`, `raw_catalog_response`
- 404 if object_uuid not found

**Endpoint 3: GET /api/observations/{observation_uuid}/anomalies**
- Returns all anomaly-flagged objects for an observation
- Query `AstronomicalObject` filtered by `source_observation_uuid` AND `is_anomaly_flagged = True`
- For each object, join latest `ObjectClassification` (most recent by `classified_at`)
- Response model: list of dicts with fields: `object_uuid`, `sky_coordinate_ra_degrees`, `sky_coordinate_dec_degrees`, `classified_object_type`, `predicted_object_type` (from ML), `anomaly_score`, `anomaly_explanation`, `catalog_object_name`, `cutout_s3_prefix`
- Return empty list (not 404) if no anomalies found

Use Pydantic response models (BaseModel classes) for clean API docs. Define them at the top of the file:
- `ClassificationResponse`
- `CrossMatchResponse`
- `AnomalyResponse`

Use `api.db.session.get_db` for the database session dependency (check existing routers for the exact import pattern).
