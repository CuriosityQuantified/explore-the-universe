**Create `web/src/components/viewer/ObservationInfo.tsx`** -- metadata sidebar:
- `'use client'` directive
- Props: `observation: ObservationDetail`, `isOpen: boolean`, `onToggle: () => void`
- Collapsible sidebar panel on the right side of the viewer
- Displays: observation ID (`archive_observation_id`), telescope, instrument, filters (join array), exposure time (format as human-readable), date (format `ingested_at`), pipeline status, pointing RA/Dec
- Also show tile metadata if available: image dimensions, tile count, zoom levels
- Dark theme: dark semi-transparent background, light text, subtle borders
- Toggle button (info icon) to show/hide

**Create `web/src/components/viewer/ImageAdjustments.tsx`** -- image controls:
- `'use client'` directive
- Props: `onAdjustmentChange: (adjustments: ImageAdjustments) => void`
- Manages local state for: brightness (0.5-2.0, default 1.0), contrast (0.5-2.0, default 1.0), gamma (0.1-3.0, default 1.0), invert (boolean, default false)
- Collapsible panel: hidden by default, expand via toolbar button per CONTEXT.md
- Range sliders for brightness/contrast/gamma with current value display
- Toggle switch for invert
- Reset button: restores all values to defaults in one click
- The parent component applies these via CSS filters on the OpenSeadragon canvas:
  - `brightness(${value})`, `contrast(${value})`, `invert(${0|1})`
  - Gamma: approximate via a combination of brightness and contrast adjustment, OR use a simple power-curve approach by adjusting the canvas via a post-render callback. For Phase 3, approximate gamma by applying `brightness(gammaFactor)` where `gammaFactor = pow(1.0, 1/gamma)` -- this is an approximation but avoids needing WebGL. Document the approximation in a code comment.
- The `onAdjustmentChange` callback passes the adjustment values to the parent, which applies `canvas.style.filter` on the OpenSeadragon canvas element

**Create `web/src/components/viewer/BandSelector.tsx`** -- filter/band switcher:
- `'use client'` directive
- Props: `spectralFilters: string[] | null`, `currentBand: number`, `onBandChange: (index: number) => void`
- If `spectralFilters` is null or has <= 1 entry, render nothing (single-band observation)
- If multiple filters: render tabs or dropdown showing filter names (e.g., "F200W", "F444W")
- NOTE: Phase 2 currently overwrites tiles for each FITS file using the same S3 prefix. This means only the LAST processed file's tiles exist in MinIO. The band selector UI should still be built so it's ready when tile isolation is added (likely Phase 6 or a future fix). For now, switching bands will reload the same tile set -- document this limitation in a code comment.
- `onBandChange` callback tells the parent to update the OpenSeadragon tile source URL (future: `{uuid}/{band_index}/tiles/`)

**Create `web/src/components/viewer/CoordinateGrid.tsx`** -- grid overlay:
- `'use client'` directive
- Props: `viewer: OpenSeadragon.Viewer | null`, `wcsParams: WcsParams`, `visible: boolean`
- Renders an SVG overlay positioned on top of the OpenSeadragon canvas
- When `visible` is true:
  1. Get current viewport bounds from the viewer (`viewer.viewport.getBounds()`)
  2. Convert viewport corners to image coordinates, then to RA/Dec using `pixelToRaDec`
  3. Compute nice grid spacing based on the field of view (e.g., 10 arcsec grid for narrow views, 1 arcmin for wider)
  4. For each grid line (constant RA or constant Dec), compute pixel positions at multiple points along the line by reverse-projecting from RA/Dec back to viewport coords
  5. Draw SVG `<line>` or `<path>` elements with labels at the edges
- Listen to viewer `animation` and `animation-finish` events to re-render grid on pan/zoom
- Off by default per CONTEXT.md -- toggled via toolbar button
- Styling: thin semi-transparent white/cyan lines, small labels at edges

- Add toolbar buttons for: info panel toggle, adjustments panel toggle, grid toggle
- Layout: viewer takes full viewport, panels overlay on top (info sidebar on right, adjustments panel in a dropdown/popover, coordinate overlay at bottom)
