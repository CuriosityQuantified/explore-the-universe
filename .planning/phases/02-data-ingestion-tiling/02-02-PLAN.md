<objective>
Implement the WCS validation and tile generation Celery tasks. The WCS task extracts and validates sky coordinates from FITS headers, storing pointing data. The tiling task converts FITS data to normalized 8-bit images and generates DZI tile pyramids using memory-safe chunked processing.

Purpose: These are the two core data processing steps between download and a viewable result. WCS provides accurate sky positioning (critical for all downstream coordinate work). Tiling produces the multi-resolution imagery that the sky viewer (Phase 3) and segmentation pipeline (Phase 4) consume.
Output: `pipeline/tasks/validate_wcs.py`, `pipeline/tasks/tile.py`
</objective>

1. Create `pipeline/tasks/validate_wcs.py` with a Celery task `validate_wcs`:
   - Signature: `validate_wcs(download_result: dict) -> dict`
   - Receives the output dict from download_fits: `{"observation_uuid": "...", "fits_s3_keys": [...], "product_count": N}`
   - This is called as the second step in the Celery chain

   Implementation steps within the task:
   a. Create a ProcessingStep record (step_name="validate_wcs", step_status=StepStatus.running)
   b. For each FITS S3 key in `fits_s3_keys`:
      - Download the FITS file from MinIO `fits-raw` bucket to a local temp file using `get_s3_client()` and `download_file()`
      - Open with `astropy.io.fits.open(fits_path, memmap=True, mode='denywrite')`
      - Find the SCI extension: check for `hdul['SCI']` first, fall back to `hdul[0]` if no named SCI extension. Verify the chosen HDU has `NAXIS > 0` (has actual image data). Log a warning if falling back to primary HDU.
      - Extract WCS using `astropy.wcs.WCS(sci_hdu.header)`
      - Validate WCS with round-trip test:
        * Define test pixel coordinates: corners + center of image `[[0,0], [nx//2, ny//2], [nx-1, ny-1], [0, ny-1], [nx-1, 0]]`
        * Convert pixels to world coords: `w.all_pix2world(test_pixels, 0)`
        * Convert back: `w.all_world2pix(world, 0)`
        * Check `max_error = np.max(np.abs(test_pixels - roundtrip))` is < 1.0 pixel
        * If validation fails, log warning but continue (some FITS may have approximate WCS)
      - Extract pointing coordinates (image center): `w.pixel_to_world(nx//2, ny//2)` to get RA/Dec in degrees
      - Extract additional provenance from FITS headers (supplements MAST metadata from Plan 01):
        * `TELESCOP` -> telescope_name
        * `INSTRUME` -> instrument_name
        * `FILTER` or `FILTER1` -> spectral_filters
        * `EXPTIME` -> total_exposure_seconds
        * Store as dict in step_output_metadata
   c. Update the Observation record:
      - `pointing_ra_degrees` = center RA (from the first/primary FITS file)
      - `pointing_dec_degrees` = center Dec
      - `pipeline_status` remains as-is (still processing)
   d. Update ProcessingStep: step_status=StepStatus.completed, step_output_metadata with:
      - `wcs_valid`: boolean (did round-trip pass)
      - `max_round_trip_error_pixels`: float
      - `center_ra_degrees`: float
      - `center_dec_degrees`: float
      - `image_dimensions`: [ny, nx]
      - `fits_header_provenance`: dict of extracted header fields
   e. On exception: update ProcessingStep to failed, update Observation to failed, re-raise
   f. Clean up local temp files
   g. Return dict: `{"observation_uuid": "...", "fits_s3_keys": [...], "wcs_valid": bool, "image_dimensions": {"ny": int, "nx": int}}`

   Database session: Use `SessionLocal()` directly (not FastAPI dependency injection).
   Import astropy at module level: `from astropy.io import fits`, `from astropy.wcs import WCS`

CRITICAL: Always check for 'SCI' named extension first before falling back to hdul[0]. JWST MEF files store science data in the SCI extension, not the primary HDU.

<task type="auto">
  <name>Task 2: Implement tile generation Celery task</name>
  <files>
    pipeline/tasks/tile.py
    pipeline/celery_app.py
  </files>
  <action>
1. Create `pipeline/tasks/tile.py` with a Celery task `generate_tiles`:
   - Signature: `generate_tiles(wcs_result: dict) -> dict`
   - Receives output from validate_wcs: `{"observation_uuid": "...", "fits_s3_keys": [...], "wcs_valid": bool, "image_dimensions": {...}}`
   - This is the third step in the Celery chain

   Implementation steps within the task:
   a. Create ProcessingStep (step_name="generate_tiles", step_status=StepStatus.running)
   b. For each FITS S3 key (typically one primary science file per observation):
      - Download FITS from MinIO to local temp file
      - Open with `astropy.io.fits.open(fits_path, memmap=True, mode='denywrite')`
      - Find SCI extension (same logic as validate_wcs)
      - Get image dimensions `ny, nx = sci_data.shape`

      **Step 1: Compute normalization parameters from subsample**
      - Compute sampling step: `step = max(1, ny // 100)` (sample ~100 rows)
      - Load subsample: `sample = np.array(data[::step, ::step], dtype=np.float32)`
      - Handle NaN/Inf: `sample = np.nan_to_num(sample, nan=0.0, posinf=0.0, neginf=0.0)`
      - Compute ZScale limits: `interval = ZScaleInterval(); vmin, vmax = interval.get_limits(sample)`
      - Create stretch: `stretch = AsinhStretch(a=0.1)`
      - Store vmin, vmax in step_output_metadata for reproducibility

      **Step 2: Chunked normalization to intermediate TIFF**
      - Define chunk_rows = 4096 (configurable, balances memory vs overhead)
      - Create a temp directory for intermediate files
      - Process FITS data in row-band chunks:
        ```
        for y_start in range(0, ny, chunk_rows):
            y_end = min(y_start + chunk_rows, ny)
            chunk = np.array(data[y_start:y_end, :], dtype=np.float32)
            chunk = np.nan_to_num(chunk, nan=0.0, posinf=0.0, neginf=0.0)
            # Normalize using pre-computed vmin/vmax
            chunk = np.clip((chunk - vmin) / (vmax - vmin), 0, 1)
            chunk = stretch(chunk)
            chunk_uint8 = (chunk * 255).astype(np.uint8)
            # Convert to pyvips strip
            strip = pyvips.Image.new_from_memory(chunk_uint8.tobytes(), nx, y_end - y_start, 1, 'uchar')
            strips.append(strip)
        ```
      - Join strips vertically: `full_image = strips[0].join(strips[1], 'vertical')` chained, or use `arrayjoin` for small strip counts
      - For truly large images (>50,000 rows): write each strip as a separate TIFF strip and concatenate, or use pyvips sequential write pattern. Add a comment documenting this threshold.
      - Save as intermediate tiled TIFF: `full_image.tiffsave(temp_tiff_path, tile=True, pyramid=True, compression='jpeg', Q=85)`

      **Step 3: Generate DZI tile pyramid**
      - Load intermediate TIFF with sequential access: `vips_image = pyvips.Image.new_from_file(temp_tiff_path, access='sequential')`
      - Generate DZI: `vips_image.dzsave(output_base, tile_size=256, overlap=1, depth='onepixel', suffix='.jpg[Q=85]', layout='dz')`
      - This creates `{output_base}.dzi` (XML metadata) and `{output_base}_files/` directory with tile levels

      **Step 4: Upload tiles to MinIO**
      - Upload DZI XML: S3 key = `{observation_uuid}/{observation_uuid}.dzi`, ContentType='application/xml'
      - Walk `{output_base}_files/` directory recursively
      - Upload each tile: S3 key = `{observation_uuid}/tiles/{level}/{col}_{row}.jpg`, ContentType='image/jpeg'
      - Use `get_s3_client()` from shared.s3
      - Upload to the `tiles` bucket (settings.s3_bucket_tiles)

      **Step 5: Record metadata and clean up**
      - Count total tiles generated, total bytes uploaded
      - Update ProcessingStep: step_status=completed, step_output_metadata with:
        * `tile_count`: int (total tiles across all levels)
        * `max_zoom_level`: int
        * `tile_size_pixels`: 256
        * `dzi_s3_key`: str
        * `normalization_vmin`: float
        * `normalization_vmax`: float
        * `image_width_pixels`: nx
        * `image_height_pixels`: ny
      - Update Observation: `pipeline_status = PipelineStatus.completed`
      - Clean up all local temp files (intermediate TIFF, DZI output directory, downloaded FITS)

   c. On exception: update ProcessingStep to failed, update Observation to failed, clean up temp files, re-raise
   d. Return dict: `{"observation_uuid": "...", "tile_count": N, "dzi_s3_key": "...", "status": "completed"}`

2. Update `pipeline/celery_app.py`:

CRITICAL memory safety:
- NEVER call `.copy()` or `np.array(data)` on the full FITS data array

- Apply same vmin/vmax to ALL chunks
