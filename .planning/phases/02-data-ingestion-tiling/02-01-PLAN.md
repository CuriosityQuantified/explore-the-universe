<task type="auto">
  <name>Task 2: Implement MAST download Celery task</name>
  <files>
    pipeline/tasks/download.py
    pipeline/celery_app.py
  </files>
  <action>
1. Create `pipeline/tasks/download.py` with a Celery task `download_fits`:
   - Signature: `download_fits(observation_uuid_hex: str, archive_observation_id: str, archive_program_id: str | None = None) -> dict`
   - The task receives a pre-created observation_uuid (hex string) from the orchestrator (Plan 03)

   Implementation steps within the task:
   a. Create a ProcessingStep record (step_name="download", step_status=StepStatus.running) in PostgreSQL
   b. Query MAST using `astroquery.mast.Observations.query_criteria()`:
      - `obs_collection='JWST'`
      - If archive_observation_id provided: `obs_id=archive_observation_id`
      - If archive_program_id provided: `proposal_id=archive_program_id`
      - `dataRights='PUBLIC'`
   c. Call `Observations.get_product_list()` on the query results
   d. Filter products with `Observations.filter_products()`:
      - `extension='fits'`
      - `calib_level=[2, 3]` (calibrated and combined products)
      - `productType='SCIENCE'`
   e. Download filtered products to the configured mast_download_directory using `Observations.download_products()`
   f. For each downloaded FITS file:
      - Upload to MinIO `fits-raw` bucket with key `{observation_uuid}/{filename}`
      - Use `get_s3_client()` from `shared.s3`
   g. Extract provenance metadata from MAST query results table (not FITS headers yet -- that's the WCS step):
      - `telescope_name` from obs_table `obs_collection` or `t_obs_collection`
      - `instrument_name` from obs_table `instrument_name`
      - `spectral_filters` from obs_table `filters`
      - `total_exposure_seconds` from obs_table `t_exptime`
   h. Update the Observation record with provenance fields (pointing_ra_degrees and pointing_dec_degrees come from WCS validation in Plan 02)
   i. Update ProcessingStep: step_status=StepStatus.completed, step_output_metadata with download manifest (list of S3 keys, file sizes, MAST product URIs)
   j. On any exception: update ProcessingStep to StepStatus.failed with error_message_text, update Observation pipeline_status to PipelineStatus.failed, re-raise
   k. Clean up local download directory after successful MinIO upload
   l. Return dict: `{"observation_uuid": observation_uuid_hex, "fits_s3_keys": [...], "product_count": N}`

   Use Celery retry with `autoretry_for=(ConnectionError, TimeoutError)`, `retry_backoff=True`, `max_retries=3` for MAST download resilience.

   Database session management: Create a SQLAlchemy session using `SessionLocal()` from `api.db.session` at the start of the task, commit/rollback/close properly. Do NOT use FastAPI's dependency injection (get_database_session) -- Celery tasks are not HTTP requests.

2. Update `pipeline/celery_app.py`:
   - Add `"pipeline.tasks.download"` to the `include=` list

CRITICAL: Use `Observations.query_criteria()` first, then pass the resulting table rows to `get_product_list()`. Do NOT pass raw obs_id strings to get_product_list -- that causes the obsid vs obs_id confusion pitfall from research.
